# План разработки «Дом-портфолио»

## Зачем

Сайт-портфолио Senior Frontend Developer Михаила Даниловича: иллюстрированный дом в разрезе, подъём по этажам скроллом, каждый этаж — проект из карьеры. Цель сайта — за 1–2 минуты показать путь и дать нанимателю отправить вакансию через форму-«домофон».

Хендофф-пакет готов: `design/SPEC.md` (поведение, состояния, анимации), `design/tokens.json`, `portfolio-content.md` (контент RU/EN), `design/mockups/` (дизайн-система + 12 экранов × 2 языка).

Результат: десктопный MVP (1440×900 опорный, резиновый от 1280), задел под мобилки без переписывания, развёрнут на Vercel.

Порядок стадий соответствует порядку из хендофф-пакета, дополненному двумя подготовительными стадиями: init-коммит → тулинг → проект.

## Согласованные решения

|             |                                                                                                                                          |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Фреймворк   | Next.js 16.4 (App Router) + React 19.3 + TypeScript                                                                                      |
| Стили       | Tailwind v4 (UI-хром) + CSS Modules (сцена), оба без рантайма                                                                            |
| Анимации    | CSS transitions/keyframes + нативный скролл + тонкий helper на WAAPI. **Без GSAP/Motion** — план Б, если exit-анимации станут неудобными |
| Камера      | Нативный скролл, без JS-перехвата. `IntersectionObserver` для фокуса этажа                                                               |

| Состояние   | React state + URL. **Без Redux/Zustand**                                                                                                 |
| Форма       | react-hook-form + Zod (одна схема на клиент и сервер), ленивый чанк                                                                      |
| Отправка    | Route Handler → Telegram Bot API, honeypot + in-memory rate limit (best-effort, осознанно)                                               |
| Тесты       | Vitest с первого кода, Playwright перед стадией домофона                                                                                 |
| Репозиторий | Публичный на GitHub                                                                                                                      |
| Коммиты     | Conventional Commits, без commitlint. Коммиты от Claude Code несут строку `Co-Authored-By`                                               |

## Стадия 0 — Init-коммит

Ставим в `.tmp-scaffold/`, переносим содержимое в корень, папку удаляем. Флаги: `--typescript --tailwind --eslint --app --src-dir --import-alias "@/*" --use-npm --no-git`

- `.env.example` с пустыми `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID`. **Репозиторий публичный — реальные значения только в `.env.local` и в env Vercel, в git не попадают никогда**
- Корневой `README.md`: что это, стек, как запустить, где хендофф-материалы. Содержимое `design/README.md` (тестовое) переезжает туда, сам файл удаляется
- `AGENTS.md` от create-next-app → переименовать в `CLAUDE.md` и вписать решения из таблицы выше, правила анимаций и ссылку на SPEC
- Этот `PLAN.md` входит в тот же коммит
- `gh repo create portfolio --public --source . --remote origin`, push
- Коммит: `chore: init project with Next.js scaffold and handoff materials`

## Стадия 2 — Токены, контент-модель, i18n

Фундамент, на который ложится всё остальное. Ничего визуального — зато сразу видно, что весь контент разложился без потерь.

- `src/styles/tokens.css` — обычный файл в репозитории, значения перенесены из `design/tokens.json` руками. Без генератора и без `predev`/`prebuild`
- Tailwind v4 `@theme` читает сгенерированные переменные
- `src/content/types.ts`: `Content`, `Floor`, `Achievement`, `PetProject`, `Roof`, `Contacts`, `Basement`
- `src/content/ru.ts`, `src/content/en.ts` — весь `portfolio-content.md`. Этажи 2–6 (нумерация дома), у каждого: `period`, `title`, `role`, `description`, `stack[]`, `achievements[]` (`{ title, text }` — заголовок рамки и полный текст), `responsibilities[]`
- **Облегчённый режим квартиры выводится из данных, а не флагом:** у Мосгосэкспертизы пустые `achievements` и `responsibilities` → рендерится только плакат (SPEC §5)
- `[locale]` route segment, реестр локалей, типизированный доступ к словарю
- `public/cv/` + пути в модели: `Mihail-Danilovich-Senior-Frontend-Developer-RU.pdf` и `-EN.pdf`. **Файлы кладёт владелец проекта**
- Проверка наличия PDF — тестом в `content.test.ts`, а не отдельным скриптом: прогоняется в pre-push, новой обвязки не требует. Добавляется, как только файлы легут в `public/cv/`. Битая ссылка на резюме — худший баг на сайте, который ищет работу
- Тесты: обе локали одинаковой формы, этажи 2–6 на месте, обязательные строки не пустые, у каждого пет-проекта есть ссылка

Критические файлы: `src/content/types.ts`, `src/content/{ru,en}.ts`, `src/styles/tokens.css`

## Стадия 3 — Сцена дома и камера

Самая большая стадия, разбита на пять подэтапов. Каждый — отдельный коммит с результатом, который видно глазами или тестом. Эталон на всю стадию: `design/mockups/ru/01-first-screen.html`.

### 3a — Геометрия

`src/scene/layout.ts` — **чистая функция** без React и DOM: абстрактные единицы → px, геометрия этажей, сетка окон, какое окно в этаже проектное, координаты подвала, двери и гаража. Параметризована вьюпортом, поэтому узкий экран меняет масштаб, а не требует переразметки.

Результат: юнит-тесты на раскладку. Визуального ничего.

Проверка: `npm run test` — этажей пять, окна не выходят за фасад, у каждого этажа ровно одно проектное окно, при смене ширины вьюпорта пропорции сохраняются.

### 3b — Дом статикой

Слои отдельными `<svg>` в позиционированных div'ах: небо / дальний план / дом / этажи / атмосфера. Переиспользуемые формы через `<symbol>`/`<use>`, как в макетах (`b-wd`, `b-wl`, `b-wp`). Координаты берутся из 3a, цвета — из токенов.

Без интерактива и без скролла.

Проверка: открыть рядом с `ru/01-first-screen.html` на ширине 1440 и сверить.

### 3c — Камера

Нативный скролл: дом — высокий документ, крыша сверху, на маунте мгновенный `scrollTo(bottom)`. Небо меняется от сумерек к дню — одна CSS-переменная. Текущий уровень — `IntersectionObserver`, **без обработчика скролла**.

Проверка: колесо вверх поднимает к крыше, 60 fps в DevTools → Performance, инерция не сломана.

### 3d — Шапка и первый экран

Шапка 72px: имя, переключатель RU/EN, «Гараж», «Резюме», тёплая кнопка «Позвонить», круглая «?». Блок слева: статус с зелёной точкой, H1, lead, две CTA. Подсказка скролла внизу. Всё из словарей, ничего захардкоженного.

Проверка: обе локали, английские строки длиннее — блоки не фиксируют высоту.

### 3e — Мини-карта, первый визит, клавиатура

Мини-карта: `scrollIntoView({ behavior: 'smooth' })`, при reduced-motion `'instant'`, `aria-current` у текущего пункта. Карточка первого визита — один раз через `localStorage`. Клавиатура: этажи, дверь/домофон, гараж фокусируемые, `aria-label` из словаря, Enter/Space = клик, фокус-кольцо 2px.

Проверка: пройти всю сцену одним Tab без мыши, мини-карта подсвечивает текущий уровень.

## Стадия 4 — Состояния объектов

Всё — `data-state` + CSS transition. JS только переключает энум.

- **Этаж**: заливка 16–18% + контур, приглушение соседей, шторы, лампа, табличка → карточка по средней линии
- Состояние этажа — **явный энум `idle | focused | entering`**, а не `:hover`. Тач-логика из SPEC (первое касание = фокус, второе = вход) тогда пишет в тот же энум, и мобильная версия не потребует второй реализации. `:hover` — внутри `@media (hover: hover)`
- **Дверь + домофон**: одна зона, створка 350 мс, свет следом 250 мс, тултип, пульс двух колец
- **Гараж**: ворота 500 мс ease-out
- **Подвал**: последовательность по въезду камеры (лампа → диплом → плашка) и **обратный порядок** при выезде. Единственное место, где CSS плох — `transition-delay` не инвертируется, поэтому тонкий helper на WAAPI
- Ореолы окон — отдельным слоем с CSS-градиентом, анимируем opacity слоя. В макетах это радиальный градиент внутри SVG; анимировать его opacity = перерисовка области каждый кадр

Эталон: `design/mockups/ru/03-scene-states.html`, `ru/02`

## Стадия 5 — Квартира проекта

- Роут `/[locale]/floor/[n]`. **Сцена живёт в layout и не анмаунтится** — отсюда непрерывность «окно в комнате то же самое». Это главный аргумент за App Router
- Влёт: координаты окна известны (сцена генерируется из данных) → `transform-origin` в центр окна, `scale` + затухание, поверх проявляется комната. ~30 строк, предсказуемо, на композиторе
- После перехода сцена уходит в `content-visibility: hidden` — смонтирована для обратного пути, но не красится
- Компоненты: плакат, маркерная доска, **полка достижений** (переиспользуется в гараже)
- Полоса навигации 60px, нижняя навигация
- Режим «только плакат» для этажа 2
- Роуты вместо внутреннего состояния: работает «назад», ссылки шарятся, страница проекта индексируется — для сайта в поиске работы это не мелочь

Эталон: `design/mockups/ru/08-apartment-vk-hr-tek.html`

## Стадия 8 — Домофон

Перед стадией подключается **Playwright**.

- Модалка 920px, focus trap, Esc, возврат фокуса на триггер
- RHF + Zod, **одна схема на клиент и сервер** — SPEC требует, чтобы серверная валидация повторяла клиентскую. «Ссылка или описание» — `superRefine`
- Ленивый чанк: RHF + Zod (~25 КБ) не попадают в начальный бандл
- Четыре состояния: пусто / ошибка (сводка со ссылками на поля, `role="alert"`, `aria-invalid`, `aria-describedby`, иконка + текст) / отправка (`aria-busy`, спиннер, волны) / успех
- Route Handler `/api/intercom` → `sendMessage`. Honeypot, in-memory rate limit по IP с комментарием о best-effort, в dev мок в консоль
- Ошибка сети → состояние ошибки с «Напишите напрямую: Telegram @f0pp1», введённые данные сохраняются
- E2E: успешная отправка с мок-адаптером, ошибки валидации, закрытие по Esc

Эталон: `design/mockups/ru/05`, `ru/06`

## Стадия 9 — Справка «?»

## Стадия 10 — Анимации, доступность, производительность

- Атмосферные циклы: облака, дым, фонари, вывеска (20–60 с)
- **Пауза offscreen**: `animation-play-state: paused` через тот же IntersectionObserver + `content-visibility: auto` на этажах. Пять дышащих окон плюс облака и дым одновременно — заметный расход батареи на телефоне
- Сквозной проход по `prefers-reduced-motion`: циклов нет, пролётов нет, состояния мгновенные
- Контраст против пар из `00-design-system.html`, прогон скринридером по сцене
- Lighthouse. Цель: LCP < 1.2 с, CLS 0, TBT близко к нулю
- Playwright: подъём до крыши, вход в квартиру, гараж, домофон, снимок при reduced-motion
