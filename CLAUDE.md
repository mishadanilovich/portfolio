# Дом-портфолио — конвенции проекта

Сайт-портфолио: иллюстрированный дом в разрезе, подъём по этажам скроллом. Подвал — учёба, этажи 2–6 — проекты, гараж — пет-проекты, крыша — статус и контакты.

**Что читать перед работой:**

- `design/SPEC.md` — поведение, состояния объектов, анимации, требования к доступности. Источник истины по поведению.
- `design/tokens.json` — все цвета, шрифты, размеры, длительности.
- `design/mockups/` — эталонные экраны (`ru/01–12`, `en/01–12`, `00-design-system.html`). Это эталон **вида**, а не код для копирования.
- `portfolio-content.md` — весь контент RU/EN.
- `PLAN.md` — стадии разработки и текущий прогресс.

## Next.js 16

Версия с ломающими изменениями относительно того, что модель помнит из обучения. **Перед написанием кода роутов, кэширования и серверных функций читать актуальные доки в `node_modules/next/dist/docs/`** (`01-app/`, `03-architecture/`). Про это же предупреждает `AGENTS.md`.

`AGENTS.md` ведёт сам Next: блок внутри перезаписывается при каждом `next dev`. Не переименовывать и не удалять — вернётся.

Что уже выяснено на практике:

- `middleware.ts` переименован в **`proxy.ts`**, лежит в `src/` рядом с `app/`, экспортирует функцию `proxy`.
- Root layout живёт в **`src/app/[locale]/layout.tsx`**, корневых `app/layout.tsx` и `app/page.tsx` нет. Редирект с `/` делает `proxy.ts`.
- `params` асинхронные: `const { locale } = await params`. Типы `PageProps<'/[locale]'>` и `LayoutProps<'/[locale]'>` глобальные, импортировать не нужно.
- Локаль в любом серверном компоненте читается через **`next/root-params`**, без прокидывания пропсов. Пригодится, когда до сцены доберутся вложенные компоненты.
- Правило `'*.css'` в `next.config.ts` ловит и **`.module.css`**. Так написано в README `@tailwindcss/turbopack`, и с этим CSS Modules тихо ломаются: файл компилируется как глобальный, классы не хешируются, а импорт отдаёт пустой объект — в разметку уезжает `class="undefined"`. Поэтому в правиле стоит `condition: { not: { path: '*.module.css' } }`. Не убирать.
- Новый роут не виден `tsc`, пока рядом лежит `.next/types` от прошлой продакшен-сборки: `tsconfig` подключает и его, и `.next/dev/types`, а union `AppRoutes` в старом файле не знает о новом адресе. Лечится `rm -rf .next/types` или свежим `npm run build`.
- После удаления или переноса роутов **чистить `.next`**: `tsconfig` подключает `.next/dev/types/**`, и устаревшие сгенерированные типы валят `tsc` ссылками на несуществующие файлы.
- По умолчанию включены Cache Components и Partial Prefetching.
- Страницы с собственным динамическим сегментом (`floor/[n]`, `garage/[slug]`) объявляют **`export const instant = false`**. Без этого dev-оверлей ругается «URL data outside of Suspense»: весь экран зависит от `params`, и оболочку для мгновенной навигации Next собрать не может. Разложить страницу по `<Suspense>` здесь нечего ради чего — данных, которые грузятся, нет вовсе, каждый адрес пререндерится целиком по `generateStaticParams`, а фолбэк дал бы только мигание пустой комнатой. `instant = false` честно говорит: навигация сюда может подождать свой статический payload. Роуты с одним корневым `[locale]` валидацию проходят и без этого.

## Токены

`src/styles/tokens.css` — обычный файл в репозитории, значения перенесены из `design/tokens.json` руками. Генератора нет.

`@theme static` обязателен. Без модификатора `static` Tailwind v4 выбрасывает неиспользуемые переменные темы — в проверке из 55 цветов в бандл попало 6. Сцена ссылается на токены прямо в SVG (`fill="var(--color-facade)"`), Tailwind такие обращения не видит, и переменные исчезли бы.

Типошкала разложена по стандартным namespace Tailwind: `--text-*` (размер), `--leading-*` (высота строки), `--tracking-*` (трекинг). Насыщенности своих переменных не имеют — в `tokens.json` это только 400/500/600, им соответствуют `font-normal`, `font-medium`, `font-semibold`. Использование: `text-h1 leading-h1 font-medium`.

Группа `size` из `tokens.json` переименована в **`--spacing-*`**: это стандартный namespace Tailwind для любых размеров, он даёт `h-header`, `w-garage-panel`, `max-w-modal`, `p-control`. Исходное `--size-*` не годилось — `size-*` в Tailwind задаёт ширину и высоту разом, и `size-header` имел бы неверную семантику. Проверено: именованные значения мирно живут рядом с числовой шкалой, `px-6` и `gap-10` работают как обычно.

`--motion-*` (длительности) лежат в `:root`, и это не обход, а единственный вариант: namespace `--duration-*` в Tailwind не существует (проверено сборкой — утилита `duration-probe` не генерируется). Длительности берутся в CSS Modules через `var(--motion-fast)` либо в разметке через `duration-(--motion-fast)`.

Именование токенов в `design/tokens.json` писалось без знания namespace Tailwind. Если очередной токен конфликтует со стандартом — **переименовывать в `tokens.css` по стандарту**, а не обходить исключениями в конфигах. `tokens.json` и макеты при этом остаются как переданы.

`--font-display` и `--font-ui` переопределяются в `globals.css` поверх значений из токенов: `next/font` регистрирует шрифты под сгенерированными именами, и литеральное `'Literata'` из `tokens.json` не разрешилось бы.

## Принятые решения и почему

Это осознанные отказы, а не упущения. Не «исправлять» без обсуждения.

| Решение                                    | Почему                                                                                                                                                                                                                                            |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Без GSAP / Framer Motion**               | 90% анимаций здесь — «энум → transition», это умеет CSS. Библиотека весила бы за ноль пользы. План Б, если exit-анимации модалок станут неудобными                                                                                                |
| **Без i18next**                            | Два языка статического контента. Типизированные словари тree-shake'аются и проверяются компилятором                                                                                                                                               |
| **Без Redux / Zustand**                    | Где ты в доме — это URL. Остального состояния на горсть useState                                                                                                                                                                                  |
| **Нативный скролл + CSS scroll snap**      | Перехват скролла ломает инерцию, адресную строку и жесты на телефоне. Это главное решение под будущую мобильную версию. Камера дискретная, и `scroll-snap-type: y mandatory` даёт это нативно: браузер физически не оставит скролл между уровнями |
| **Квартира и гараж — роуты, не состояние** | Работает «назад», ссылки шарятся, страницы проектов индексируются. Сцена живёт в layout и не анмаунтится — отсюда непрерывность влёта в окно                                                                                                      |
| **Tailwind для UI, CSS Modules для сцены** | Оба без рантайма. В сцене нужны keyframes и сложные селекторы, в хроме — быстрая раскладка                                                                                                                                                        |

## Правила сцены

Нарушение любого из них бьёт по производительности, особенно на телефонах:

1. Анимируем **только `transform` и `opacity`**. Никаких фильтров, блюров, анимации градиентных стопов.
2. Анимируем **обёртку-`div` транзформом, никогда SVG-атрибуты** (`x`, `y`, `d`, `width`) — это рерастеризация геометрии каждый кадр. CSS-`transform` на самом SVG-элементе — такая же ловушка: геометрия SVG считается через layout, и замер дал **60 layout'ов в секунду** на `transform` у `<circle>` и `<g>` против нуля у div'а. Layout тянет за собой перерисовку всего слоя, а слой у нас во весь дом. Поэтому всё анимируемое живёт в позиционированных div'ах рядом со статичным SVG — как `.glow`, `.gate`, `.garage-light`, облака и дым.
3. Слои — отдельные `<svg>` в позиционированных div'ах: небо / дальний план / дом / этажи / атмосфера.
4. Состояния объектов — **явный энум** (`idle | focused | entering`) через `data-state`, а не `:hover`. Тач-логика из SPEC (первое касание = фокус, второе = вход) пишет в тот же энум. `:hover` — только внутри `@media (hover: hover)`.
5. Циклические анимации — внутри `@media (prefers-reduced-motion: no-preference)` и на паузе за пределами экрана.
6. Геометрия дома — в абстрактных единицах с одним коэффициентом в px. Узкий вьюпорт меняет масштаб, а не раскладку.
7. Сцена рисуется в масштабе состояния **B** (фокус), а общий план **A** получается отъездом `scale(0.625)`. Апскейла выше 1:1 не возникает нигде, поэтому браузеру не нужно перерастеризовывать слой в пике наезда. Следствие: **никакого `vector-effect: non-scaling-stroke`** — линии должны масштабироваться вместе со сценой, иначе пропорции макета поедут.
8. `will-change: transform` ставится классом на время перехода и снимается после. Оставленный насовсем на слоях высотой в несколько экранов, он съедает видеопамять и даёт «шашечки» при скролле.
9. Таблички и тултипы — HTML поверх сцены, не внутри масштабируемого SVG, иначе текст плывёт в B. Во время наезда они скрыты и проявляются после.

## Сцена: единицы, цвета, порядок слоёв

Коэффициент px на единицу живёт в CSS: `--u` на `.camera` считается как `clamp(1280px, 100cqw, 1440px) / 960`, `--u-focus` — это `--u × 1.6`, масштаб состояния B. Формула повторяет `createSceneLayout().scale`, и это осознанное дублирование: CSS не умеет импортировать TS, а задать переменную из JS нельзя — первый экран тогда прыгал бы из B в A при гидрации. `100cqw` работает только потому, что `container-type: inline-size` стоит на `.viewport`, а переменные объявлены **на потомке**: контейнер себя самого не опрашивает.

Цвета: `var(--color-*)` там, где в `tokens.json` есть точно такой hex (`fill="var(--color-facade)"` в SVG работает — презентационные атрибуты парсятся как CSS). Случайные цвета иллюстрации, которых в токенах нет — книги в подвале, горшки, ворота гаража — остаются литералами из макета. Не придумывать под них токены: `tokens.json` передан как есть.

Ореолы окон лежат **между стенами и деталями**, а не поверх сцены: в макете `b-glow` нарисован после фасада и до окон, и если положить их сверху, тёплая плёнка смывает силуэт и шторы.

**Единицы в keyframes.** Перенося анимацию из SVG в div, смещения надо переводить: в SVG `translate(7px)` — это 7 единиц сцены, в div'е это настоящие пиксели. В keyframes пишем `calc(7 * var(--u-focus))`, иначе движение перестаёт масштабироваться вместе со сценой и на общем плане выглядит иначе, чем в фокусе.

Циклы атмосферы — **только облака и дым из трубы**. Дыхание ореолов, мерцание огней в соседних домах, пульсация фонарей и огонька вывески были сделаны и сняты по решению владельца: сцена не должна мельтешить, пока человек читает таблички этажей. Пульс домофона к этому набору не относится — он из SPEC §10 и живёт с восьмой стадии.

**Пауза циклов.** Над квартирой и гаражом делать нечего: `content-visibility: hidden` на слоях убирает анимации совсем — замер дал ноль идущих из восьми. Под модалкой сцена видна, поэтому там своё правило на `body:has(dialog[open])`. За пределами экрана камера переиспользует свой `IntersectionObserver`: элементам с `data-cycle` ставится `data-idle`, по которому включается `animation-play-state: paused`. Поэтому у дыма тесная обёртка вместо слоя во весь дом — слой виден всегда, и наблюдателю не за что зацепиться. Следствие: на общем плане дым и дневные облака стоят, потому что сцена высотой 1710 px не влезает в окно 900 px и верх кадра просто не виден.

**Мгновенные переходы под `prefers-reduced-motion`** задаёт одно правило в `globals.css`: `transition-duration` и `transition-delay` в ноль через `*` и `!important`. SPEC §10 требует «смена состояний мгновенно», а переходов в проекте больше полусотни, и расставлять полсотни переопределений — верный способ забыть про следующий. Правило трогает **только переходы**: циклы и без того живут в `@media (prefers-reduced-motion: no-preference)`, анимации входа модалок гасятся у себя, а `animation-*` не задевается намеренно — у неба `animation-timeline: scroll()`, и обнуление длительности сломало бы отображение высоты в цвет неба. JS-движение (наезд, перелёт, пролёт мини-карты) проверяет `matchMedia` в `Camera.tsx` само.

Ширина таблички — **136 единиц, а не 128 как в макете**. В макете SVG-текст не переносится и спокойно вылезает за рамку; в HTML так нельзя, а самое длинное название «Налоговая система» занимает 114.7 единицы против 110 доступных, и SPEC §11 требует перенос ровно в две строки. Макеты приведены к 136.

## Камера

Два состояния живут в разной разметке, и это главное, что надо помнить. В **A** `.camera` — `position: absolute; bottom: 0`, скроллить нечего. В **B** она в потоке, а скроллит `.viewport`. Переключает `data-camera` на `.viewport`: `overview | transition | focus`. Первый экран приходит с сервера как `overview`, то есть без JS и без прыжка при гидрации.

Переход считается в разметке **B**: сначала переключаем структуру и ставим `scrollTop` на нужный уровень, потом вешаем трансформ, который визуально воспроизводит A, и уводим его в единицу за 900 мс. Формула A в координатах B: `translate(ox, vh + scrollTop − scale·sceneH) scale(0.625)` при `transform-origin: 0 0`. Обратный переход — та же формула со `scrollTop` нижнего уровня.

Состояние камеры висит на `<body>` (`data-camera`, `data-level`), а не на контейнере сцены: по нему стилизуется и шапка, и дальше мини-карта, а они сцене не потомки. Возврат на общий план приходит извне — кнопка «Весь дом» шлёт событие через `src/scene/camera-events.ts`, камера его слушает. Так ни шапке, ни правому столбцу не нужен ни контекст, ни провайдер поверх всего дерева ради одного сигнала.

Шапка лежит поверх сцены и потому `pointer-events: none`, а `auto` возвращается самим ссылкам и кнопкам. Иначе колесо над её 72 пикселями не доходит до скроллера: шапка сцене не родитель, и событие просто теряется.

**Пока камера едет, `IntersectionObserver` не слушают.** Наезд анимирует трансформ `.camera`, и полосы уровней физически проезжают через центральную линию — наблюдатель честно докладывал про каждый этаж, и по дороге на крышу подряд вспыхивали фокусом все этажи. То же при пролёте мини-карты: плавный скролл проходит промежуточные уровни. Теперь уровень назначается сразу целевой, а отчёты наблюдателя принимаются только в состоянии `focus` и вне программного пролёта; флаг снимает событие `scrollend` (с запасным таймаутом для браузеров без него).

Уровни — элементы `.band` со `scroll-snap-align: center`: один элемент служит и точкой снапа, и мишенью `IntersectionObserver` с `rootMargin: '-50% 0 -50% 0'`. Поэтому полосы идут встык: иначе центральная линия попадает в разрыв между ними и текущий уровень на миг теряется.

**`.below` обязан прятаться в `overview`.** Это распорка, которая добавляет странице высоту, чтобы нижний уровень мог встать по центру. Если её не скрыть, в общем плане появляется скроллируемая высота, scroll-таймлайн неба считается активным, прогресс равен нулю — и на первом экране вместо сумерек день.

Небо переключается `animation-timeline: scroll(nearest block)` с `animation-range` от уровня крыши до уровня третьего этажа. Диапазон именно по уровням, а не `0% 60%`: уровень крыши стоит не в нуле трека, и при процентах день не успевает набрать полную непрозрачность. Где scroll-driven анимаций нет, слой остаётся в базовом `opacity: 0` — всегда сумерки.

## Первый экран

Текст первого экрана прячется в крупном плане чистым CSS, по `body:not([data-camera='overview'])`: `opacity 0`, `translateX(-24px)` за 300 мс и `visibility: hidden` с задержкой в те же 300 мс. Задержка нужна, чтобы блок исчезал из дерева доступности и из таба **после** затухания, а не в его начале. На обратном пути `visibility` возвращается мгновенно, и текст появляется последним сам собой: `data-camera` переключается в `overview` только по окончании отъезда камеры.

Однострочным подписям (статус, подсказка скролла) нужен явный `line-height: normal`. Preflight Tailwind ставит всему `line-height: 1.5`, у `overline` в `tokens.json` высоты строки нет вовсе, и без этого статус становится на 4 px выше — а дальше весь блок уезжает вниз, потому что высоты складываются через `gap`.

## Порядок в разметке и порядок табов

В `layout.tsx` порядок детей `<body>` — шапка, первый экран, мини-карта, сцена: это и есть порядок обхода с клавиатуры, и он совпадает с тем, как читается экран. Рисование порядком разметки не управляется, за него отвечают `z-index` (шапка и мини-карта 2, первый экран 1, сцена без слоя), поэтому сцену можно держать последней, хотя она лежит под всем.

Объекты сцены — настоящие `<button>` поверх слоёв, внутри `.camera`, координаты из `layout.ts`. Кнопки, а не `div` с `role`: Enter и Space тогда работают сами, без обработчика клавиш. Кольцо фокуса 2 px `--color-lamp-text`, как требует SPEC §11.

У текущего пункта мини-карты стоит `aria-current`, и этого достаточно — строку вида «вы здесь» в `aria-label` добавлять не надо, скринридер объявит и то и другое. По этой причине из словарей убрана `miniMap.entranceCurrent`: она была списана со статической разметки макета.

## Состояния объектов

Фокус сцены — одно значение на `<body data-focus>`: id уровня, `door` или `garage`. Его пишет `useFocusTarget`, складывая наведение мышью и текущий уровень камеры: наведение главнее, при уходе курсора возвращается уровень. Тач ничего особенного не требует — первое касание этажа просит камеру встать на него, и состояние приходит тем же путём, что от скролла.

Этажи дополнительно получают `data-state` (`idle | focused | dimmed`) на каждый элемент с `data-floor`: так в CSS один селектор вместо пяти повторов на каждое свойство. Один и тот же атрибут носят группа в оверлее, ореол окна и обёртка таблички с карточкой, поэтому все три реагируют на один проход контроллера.

**Обратный порядок в подвале делает CSS, а не WAAPI.** Задержка «на выход» живёт в базовом правиле, «на вход» — в активном: у лампы `transition-delay: 700ms` по умолчанию и `0s` при `body[data-level='basement']`, у плашки наоборот. Въезд идёт лампа → диплом → плашка, выезд разворачивается сам: плашка → диплом → лампа. Отдельный helper на таймлайнах не понадобился.

Ворота гаража поднимаются обёрткой с `overflow: hidden` и `translateY` на внутреннем полотне, а не `scaleY`: при масштабировании шаг ламелей сжимался бы вместе с полотном, а оно должно уезжать за верхний край с постоянным шагом.

Слои сцены — `pointer-events: none`, `auto` возвращается только кнопкам объектов. Иначе верхний слой-обёртка (таблички) перехватывает указатель на всю сцену и ховер не доходит до этажей.

## Квартира и влёт в окно

Квартира — роут `/[locale]/floor/[n]`, сцена живёт в layout и остаётся смонтированной. Этажи сцены из-за этого **ссылки `<Link>`, а не кнопки**: у квартиры есть адрес, его надо шарить и индексировать. Платой идёт `onKeyDown` на Space — у ссылок его нет, а SPEC §11 требует Enter/Space. Дверь и гараж остаются кнопками: дверь открывает модалку.

Первый клик не по текущему фокусу (тач или камера на другом уровне) — `preventDefault()` и `requestLevel`. Решение принимается по значению `useFocusTarget`: у мыши ховер уже поставил фокус на этаж, и клик входит сразу; на тач-устройстве ховера нет, поэтому первое касание наводит камеру, второе входит. Модифицированный клик (Ctrl, Shift, средняя кнопка) не трогаем — открытие в новой вкладке должно работать.

Шапка над любым экраном поверх сцены **непрозрачная**: обычный её фон — `color-mix` с прозрачностью, чтобы на общем плане сквозь неё читалась сцена, но над скроллящейся панелью квартиры или проекта сквозь неё просвечивал уезжающий текст.

**Признак открытой комнаты — `data-room` на `<main>`, и его обязан снимать эффект при размонтировании.** Next 16 оставляет покинутую страницу в DOM, спрятав её инлайновым `display: none`, так что `body:has([data-room])` без этого прилипает навсегда: вернувшись в дом, видишь пустую сцену и спрятанную мини-карту. Атрибут отрисован и на сервере — на прямой загрузке комнаты сцена, мини-карта и «Весь дом» прячутся без мигания до гидратации.

Перелёт — WAAPI на `.viewport`: `transform-origin` в центр проектного окна, `scale` до 2.2 и `opacity` в ноль за 700 мс. Координаты окна берутся долей от `getBoundingClientRect()` камеры (`(center − SCENE_LEFT) / SCENE_WIDTH`), поэтому формула одна и для общего плана, и для фокуса — трансформы камеры учтены самим прямоугольником. На время перелёта `body[data-fly]` поднимает сцену над комнатой (`z-index: 1`) и ставит `will-change`; из-за этого **комнате не нужна анимация появления**, она просто открывается из-под сцены, а переход комната→комната не моргает. Обратный перелёт сначала мгновенно ставит камеру на уровень своего этажа, потом разворачивает ту же анимацию от того же окна.

**`.viewport` на время экрана поверх сцены теряет `pointer-events`.** Она фиксированная во весь экран и в фокусе — скроллер со своим `overscroll-behavior`, поэтому колесо над квартирой или панелью проекта доставалось ей, а не странице: текст просто не скроллился. Слои и так спрятаны, терять ей нечего.

Сцену гасит `content-visibility: hidden` **на слоях, а не на `.viewport`**: `.viewport` — это скроллер, его `scrollHeight` схлопнулся бы вместе с содержимым и `scrollTop` уехал. Переход дискретный (`transition: content-visibility 0s allow-discrete`), задержка 700 мс живёт в активном правиле, а базовое держит `0s` — вход ждёт конца перелёта, возврат мгновенный. На прямой загрузке перехода нет вовсе (первый расчёт стиля), и сцена спрятана сразу. При `prefers-reduced-motion` задержка снимается, а перелёт не запускается — камера просто встаёт на уровень.

**Стрелки переходов рисуются иконками, а не глифами `↓`/`↑`.** В Golos Text этих символов нет, и `next/font` подставляет не системный шрифт, а свой метрически подогнанный фолбэк — стрелка выходит тоньше и выше соседних букв, будто из чужой гарнитуры. Поэтому в словарях остались только «Этаж {floor}», а направление даёт `<svg aria-hidden>` с тем же `stroke-width: 1.6`, что у чеврона «Выйти к дому». Макеты `08` приведены к тому же.

Вся навигация квартиры — полоса под шапкой: выход к дому и соседние проекты. Нижней навигации нет и крыши в полосе нет (убрано из SPEC §5 и макетов `08`): вниз она дублировала полосу, а на крышу ведут мини-карта и общий план. Поэтому `requestFlyOut` принимает только этаж — уровень возврата всегда свой.

Переключатель языка стал клиентским (`LanguageSwitch`, `usePathname`): из квартиры RU/EN обязаны вести в ту же квартиру, а не на первый экран.

## Гараж

Гараж — роут `/[locale]/garage`, экран поверх сцены по той же механике, что квартира. Признак `data-room` общий для всех таких экранов (у гаража значение `garage`), его по-прежнему снимает эффект при размонтировании.

**У гаража нет уровня камеры** (SPEC §2: гараж сбоку у земли, а не уровень), поэтому влёт и вылет его не двигают — выйдешь туда же, откуда зашёл: с общего плана на общий план, с этажа на этаж. `requestFlyIn`/`requestFlyOut` принимают либо номер этажа, либо `'garage'`; origin влёта для гаража — центр ворот.

В гараж ведут два входа: объект в сцене и пункт мини-карты — оба просят влёт. Из шапки «Гараж» убран, так что прямого пути из квартиры в гараж больше нет: сначала «Выйти к дому». Проверка «экран поверх сцены уже открыт» в камере осталась — она дешёвая и страхует влёт, пришедший не от сцены.

**`overflow: hidden` на корне экрана делает его скролл-портом, и `position: sticky` у полосы начинает считать `top` от него** — полоса уезжала вниз ровно на высоту шапки и накрывала панель. Липкость включается пропом `sticky` и нужна только в квартире: там страница длинная, в гараже она ровно в экран.

Сцена гаража тянется `preserveAspectRatio="xMidYMax slice"`, а бирки — HTML поверх неё, и их надо пересчитывать тем же масштабом. `.stage` объявлен size-контейнером, бирка берёт `--scale: max(calc(100cqw / 960), calc(100cqh / 768))` и ставится как `left: calc(50% - (480 - x) * var(--scale))`, `top: calc(100% - (768 - y) * var(--scale))` — ровно формула `slice` с якорями xMid и yMax. Деление длины на число в `calc()` допустимо, обратное — нет, поэтому масштаб хранится как длина и умножается на безразмерные координаты.

**Синхронный ховер сделан на CSS, без состояния.** На `.body` живут две переменные-переключателя (`--fridgemind`, `--coffee-shop`), их поднимают четыре правила через `:has([data-project='…']:hover)` и `:focus-visible`. Объект сцены, бирка и карточка носят один и тот же `data-project`, поэтому наведение на любой из трёх зажигает всю тройку, а каждый элемент переводит общую переменную в свою `--active`. Эффекты читают только `--active`: `opacity` у света и приглушения, `scaleX` у дверцы, `scaleY` у струйки, `color-mix` и альфа тени у карточки. Правило `data-state` из «Правил сцены» сюда не тянется: в гараже нет тач-логики в два касания и камера состояние не пишет, зато экран остаётся полностью серверным.

Дверца холодильника не перерисовывается, а сжимается: `scaleX(0.811)` от левого края — ровно отношение открытой двери к закрытой в макете (146/180), поэтому фото и записка на ней сами уходят в перспективу, а ручка уезжает туда же, куда её нарисовал макет. Нутро холодильника нарисовано всегда и просто закрыто дверцей.

Кадр сцены шире рисунка: `viewBox="-160 0 1280 768"` при объектах в прежних координатах. Иначе на окне ниже 900 px `slice` срезал **верх** — ворота и лампа уходили под полосу, и казалось, что шапка наезжает на мастерскую. Теперь при нехватке высоты обрезаются бока, где только стена, пол и ворота. Центр кадра остался на 480, поэтому формула бирок и хотспотов не изменилась — только знаменатель в `--scale`.

Кромка открытой дверцы лежит **внутри** группы двери и только проявляется по `opacity`: отдельным элементом она вспыхивала на конечном месте, пока дверь ещё ехала. Нарисована она у правого края закрытой двери (x 300–307) и приезжает на макетные 266–273 тем же `scaleX`.

Приглушение второго объекта — две полупрозрачные плашки на половину сцены. Класс `.dim` с `data-object='fridgemind'` закрывает **правую** половину: атрибут называет того, кто наведён, а не того, кого гасим.

Страница пет-проекта — тот же экран гаража, но с подсветкой одного объекта: `--fridgemind` или `--coffee-shop` ставится инлайном на `.body`, а приглушение второго усиливается множителем `--dim-strength`. Правила ховера висят на `.body[data-live]`, который ставит только список, — на странице проекта наведение не перебивает фокус.

Со страницы проекта можно уйти к соседнему прямо из сцены: хотспот рисуется только у **чужого** объекта. Выбранный проект живёт в `data-focus` на `.body` и поднимает свою переменную правилом, а правила ховера поднимают свою и **гасят чужую** — поэтому наведение на соседа честно забирает подсветку себе и отдаёт обратно, когда курсор ушёл. Инлайновый стиль для этого не годится: его стилями не перебить.

Панель там длиннее экрана, поэтому страница скроллится, а сцена **прибита `position: sticky`** на высоту окна: иначе она растягивалась бы вместе с панелью и `slice` зумил бы интерьер тем сильнее, чем длиннее текст. В макетах `10` и `12` страница, наоборот, втиснута в фиксированные 1040 px, и флексы там сжали ссылку «Все пет-проекты» с 44 px до 20 — это артефакт макета, не замысел.

Полка достижений — общий компонент `components/Shelves.tsx` с вариантами `large` (квартира: рамка 8 px, заголовок) и `small` (гараж: рамка 5 px, только текст, бумажная подложка). Размеры разведены переменными внутри модуля, разметка одна. Функция раскладки по две рамки живёт там же: отдельный `shelves.ts` рядом с `Shelves.tsx` снова упёрся бы в регистр имён на Windows.

Файл логики называется `projects.ts`, а не `garage.ts`: на Windows `garage.ts` и `Garage.tsx` различаются только регистром, и TypeScript падает с TS1149.

## Комната: раскладка и типографика

Комната — обычная HTML-страница поверх сцены, не масштабируемая сцена: шапка фиксирована, полоса этажа липнет под ней на `var(--spacing-header)`, содержимое идёт полосой `max-width: 1440` по центру.

Макет свёрстан в `content-box`, у нас глобальный `border-box` из preflight — поэтому **высоты с рамкой складываем руками**: полка `16 + 4 = 20`, пол `120 + 10 = 130`. Иначе рамка съедает тело полки и весь низ комнаты уезжает.

Заголовок плаката 52 px не всегда влезает в 480-пиксельный плакат: доступно 396 px, а «Мосгосэкспертиза» занимает 493 px (замер `canvas.measureText` в реальном шрифте). Слово длиннее 13 символов включает `data-long` и 40 px — при нём помещаются и «Мосгосэкспертиза» (380), и «Mosgosexpertiza» (326). Перенос по слогам не годится: словари переносов в Chrome приезжают компонентом, и в чистом профиле слово рвётся без дефиса.

Достижения кладутся по два на полку (`shelves()`), одинокая рамка остаётся в своей половине: `flex: 0 1 calc(50% - 16px)` без роста. Облегчённый режим (`isSolo`) выводится из пустых списков, а не из флага, и центрируется по вертикали: кроме плаката и окна в комнате ничего нет.

## Крыша

Крыша — не роут, а уровень сцены, поэтому карточка статуса живёт на главной рядом с первым экраном и показывается по `body[data-level='roof']`: `visibility` снимается сразу, а прячется с задержкой в длительность перехода, чтобы карточка уходила из таба и из дерева доступности после затухания, а не в его начале.

Текст вывески — HTML поверх сцены по тому же правилу, что таблички: внутри SVG он бы плыл при масштабе. Размеры заданы в единицах сцены (`calc(18.7 * var(--u-focus))` и далее), и это пропорции макета `07`, пересчитанные из его доски 270×84 в нашу 180×56. Появляется текст только в крупном плане: в макете `01` доска пустая, и первый экран должен сходиться с ним попиксельно.

Карточка перекрывает левый угол вывески — у макета `07` своя композиция крыши, а наша рамка задана SPEC §2 (по центру «фасад и таблички»), сдвинуть нечего. В русской локали за карточкой прячется огонёк перед «ОТКРЫТ», в английской он виден.

Внешние ссылки на крыше и в гараже открываются в новой вкладке — уходить из дома по ним незачем. Резюме и почта остаются в текущей: первое скачивается файлом, второе отдаётся почтовому клиенту, и пустая вкладка в обоих случаях лишняя. Внутри каждой внешней ссылки лежит скрытая подпись «откроется в новой вкладке»: иначе скринридер о смене вкладки не предупредит.

Кнопка копирования email меняет иконку на галочку и свою `aria-label`, а рядом лежит скрытый `role="status"` — без него по клику мышью не было бы никакого подтверждения для скринридера. Отказ `navigator.clipboard` (нет разрешения, небезопасный контекст) глотается молча: подсказки «скопируйте вручную» в хендоффе нет, а ломать кнопку ошибкой нельзя.

## Домофон

Модалка — **нативный `<dialog>` с `showModal()`**. Ловушка фокуса, Esc, возврат фокуса на триггер и верхний слой достаются от платформы; своего focus trap нет по той же причине, по какой нет GSAP.

Tailwind preflight ставит `margin: 0` всему подряд и этим ломает штатную центровку диалога (`inset: 0` + `margin: auto` из UA-стилей) — **`margin: auto` возвращается руками**. По той же причине `display: flex` стоит на `.dialog[open]`, а не на `.dialog`: авторский `display` на закрытом диалоге перебивает `dialog:not([open]) { display: none }`, и модалка висит на странице всегда.

Вход анимируется `@keyframes` на `[open]`, выхода нет: без `transition-behavior: allow-discrete` на `display` и `overlay` элемент покидает верхний слой мгновенно, а эти свойства ещё не во всех сборках `stylelint` известны. Мгновенное закрытие честнее мерцания.

Открывают модалку четыре места — дверь в сцене, «Позвонить» в шапке, CTA первого экрана и CTA крыши. Сигнал идёт событием через `src/intercom/events.ts`, как возврат на общий план: шапке и крыше не нужен ни контекст, ни провайдер. Дверь повторяет логику этажей — если фокус сцены не на ней (тач, камера на другом уровне), первый клик наводит камеру на уровень входа, второй открывает модалку.

Тело модалки (панель и форма) грузится `next/dynamic` отдельным чанком: RHF и Zod не должны попадать в начальный бандл. Чтобы первое открытие не показывало пустую рамку, чанк прогревается в `requestIdleCallback` (в браузерах без него — таймером). Первый фокус детерминированный: форма наводит его на «Закрыть» эффектом при монтировании, дальше это делает сам `showModal`.

**Скролл сцены под модалкой гасится `pointer-events: none` на `.viewport`** — тем же приёмом, что для комнат. Менять `overflow` у скроллера нельзя: он потеряет `scrollTop`.

Камера перестала просыпаться от клавиш, когда событие пришло с `<button>`: Space на кнопке — это её активация, а не намерение прокрутить. Раньше гасились только поля ввода, и пробел на «Позвонить в домофон» открывал бы модалку и одновременно запускал наезд. Отдельной проверкой камера молчит, пока открыт любой `dialog[open]`.

Однострочным подписям формы нужен явный `line-height: normal` — та же история, что со статусом первого экрана: preflight ставит всему `1.5`, и каждая подпись становится на 5 px выше, а дальше расхождение копится вниз по форме.

**Сервер — один Route Handler `/api/intercom`.** Схема Zod собирается фабрикой от словаря локали (`intercomSchema(errors)`), поэтому клиент и сервер проверяют одно и то же и отвечают на языке сайта: локаль приезжает в теле запроса, по ней выбирается словарь. `proxy.ts` `api/` не трогает, своего `[locale]`-сегмента у роута нет.

Требование «ссылка **или** описание» живёт в `superRefine` и кладёт одну и ту же ошибку на оба поля: в макете `06` обведены оба, а сообщение под ними одно.

**Honeypot проверяется до ограничителя и отвечает `{ ok: true }`.** Поле не в схеме намеренно: будь оно там, автозаполнение браузера у живого человека дало бы ошибку на невидимом поле. Бот же должен думать, что всё прошло.

Ограничитель частоты — `Map` в памяти процесса, пять попыток на IP за десять минут. На serverless это best-effort: инстансов несколько, память у каждого своя, при простое она уходит. Осознанно: это заслон от случайного спама, а не защита.

Отсутствие `TELEGRAM_*` в окружении в dev печатает сообщение в консоль, в проде это 502 с текстом «Напишите напрямую». `next start` всегда ставит `NODE_ENV=production`, поэтому мок проверяется только на `next dev`.

**В `.env.local` лежат рабочие токены, и локальный POST на `/api/intercom` уходит в настоящий Telegram.** Для проверок эндпоинта поднимать сервер с пустыми `TELEGRAM_BOT_TOKEN=` и `TELEGRAM_CHAT_ID=`.

**`@hookform/resolvers` стоит версии 5, а не 6, и это не каприз.** Шестёрка объявляет два десятка необязательных peer-зависимостей — по одной на каждый поддерживаемый валидатор, — и две из них конфликтуют между собой: сам пакет просит `effect@^4`, а его же `@typeschema/main` тянет `@typeschema/effect` → `@effect/schema`, которому нужен `effect@^3.6.8`. npm не может выбрать одну версию и падает с ERESOLVE. От нашего дерева это не зависит: `effect` у нас нет вовсе, и без пина версии (`npm i @hookform/resolvers`) результат тот же. Пятёрка ставится чисто, `zodResolver` в ней тот же и zod 4 поддерживает (`peerDependencies.zod` — `^3.25.0 || ^4.0.0`).

Honeypot читается из `FormData` формы в обработчике сабмита, а не через `ref`: правило `react-hooks/refs` считает чтение `ref.current` внутри колбэка, переданного в `handleSubmit`, чтением во время рендера.

**Высота модалки — `min-height: 740px`, а не фиксированная.** 740 — это макет `05` в окне 1440×900, но состояние ошибки добавляет сводку и два сообщения под полями, и при жёсткой высоте кнопка «Позвонить» уезжала под нижний край. В макете `06` это решено высотой 820; у нас модалка растёт сама и упирается в `calc(100dvh - 48px)`.

Первое слово в сводке ошибок поднимает регистр **в JS**, а не `::first-letter`: псевдоэлемент работает только у блочных боксов, а ссылки внутри сводки строчные.

Состояния устройства в левой колонке переключает `data-state` на `<svg>`, а заливки лежат в CSS-модуле. Волны и ореол при наборе и дозвоне нарисованы всегда и управляются `opacity` и `fill-opacity` — ровно по правилам сцены, хотя модалка сценой и не является.

Повторное открытие после успеха возвращает форму: `IntercomBody` сам слушает `intercom:open` и, если на экране подтверждение, сбрасывает его. Набранный, но не отправленный текст при этом остаётся — закрыть по Esc и вернуться не значит потерять написанное.

## Правый столбец управления

Шапка несёт только то, что относится ко всему сайту: RU/EN, «Резюме» и тёплую кнопку «Оставить вакансию». Навигация по дому вынесена в правый столбец поверх сцены: «?» под шапкой (`top: 90`), а ниже — `SideControls` с мини-картой и «Весь дом». Всё в одном оформлении и на `right: 18`.

**Мини-карта центрируется по высоте окна, а кнопка висит над ней абсолютом** (`bottom: calc(100% + 8px)`). Это не каприз: если бы обе лежали в одном потоке, мини-карта прыгала бы на 52 px каждый раз, когда «Весь дом» появляется и исчезает. Теперь центр держит одна мини-карта, а кнопка приходит и уходит, ничего не двигая. Высота мини-карты выводится из содержимого, поэтому в CSS её нигде нет.

Ниже 767 px по высоте центровка отключается и столбец прибивается к `top: 194`: на коротком окне (ноутбук 1366×768 даёт около 650 px вьюпорта) центрированная кнопка наехала бы на «?». 767 — это ровно та высота, при которой центр ещё даёт 194.

«Весь дом» стала иконкой из четырёх угловых скобок — это «развернуть», и подпись ушла в `aria-label`. В словарях она переехала из `ui.header.overview` в `ui.scene.overview`: шапки она больше не касается, зато командует камерой. Прячется кнопка в двух случаях — `visibility: hidden` на общем плане, где отъезжать некуда, и `display: none` над комнатой вместе со всем столбцом. Правило скрытия в комнате теперь одно, на `.column`: своё у мини-карты убрано, иначе источников правды два.

«Гараж» из шапки убран совсем: в гараж ведут объект в сцене и мини-карта, а `GarageLink` удалён за ненадобностью. Побочный эффект — из квартиры в гараж одним кликом больше не попасть.

Благодаря этому шапка наконец сходится с макетами попиксельно: раньше в ней всегда висел «Весь дом», спрятанный через `visibility: hidden`, и ряд был на 110 px шире макетного.

## Справка «?»

Кнопка «?» живёт **не в шапке, а отдельным кругом 44 px под ней** (`right: 18`, `top: 90`) в оформлении мини-карты: это навигация по дому, а не пункт шапки. Общий вид обеих плавающих кнопок лежит в `components/controls.module.css`: `.control` — рамка, фон и кольцо фокуса, `.help` и `.overview` — только `top`. В разметке она идёт сразу за шапкой, поэтому с клавиатуры попадаешь на неё там же, где и раньше, — следом за «Позвонить». Подпись переехала из `ui.header.help` в `ui.help.open`.

**Над комнатой и гаражом кнопка прячется** тем же правилом `body:has([data-room])`, что мини-карта и «Весь дом». Справка рассказывает про этажи, мини-карту и дверь — внутри проекта по ней действовать нечем, а свободного угла там нет: полоса этажа занимает всю ширину, её правый край в квартире держат ссылки на соседние проекты, а ниже в гараже стоит панель на 480 px.

Модалка справки повторяет механику домофона: нативный `<dialog>`, сигнал на открытие событием через `src/help/events.ts`, `margin: auto` и `display: flex` на `[open]` руками поверх preflight, вход анимацией на `[open]` без выхода. Прокрутку сцены под ней и клавиши камеры гасят уже существующие общие правила на `dialog[open]` — своего ничего не понадобилось.

Содержимое статическое, поэтому `next/dynamic` здесь нет: тело приезжает с сервера целиком. Схема дома передана пропом `scheme`, а не нарисована внутри клиентского компонента — инлайновый SVG на 350×420 не должен уезжать в клиентский бандл.

Ширина 960 px стоит литералом: в `tokens.json` есть только `modalWidth: 920` под домофон, и второй токен ради одного экрана не заводился.

Подвала у модалки нет: «Понятно» стоит в правой колонке и прижата `margin-top: auto` к её низу, а колонка тянется `align-self: stretch` до высоты схемы — поэтому кнопка всегда встаёт вровень с нижним краем дома, какой бы длины ни оказались пункты.

Правила сцены на схему не распространяются: это статичная картинка фиксированного размера, она не масштабируется и ничего не анимирует.

Карточка первого визита живёт на главной (`page.tsx`), а не в layout: её стрелка указывает на «?», а над комнатой и гаражом кнопки нет вовсе. В разметке она идёт перед первым экраном, поэтому с клавиатуры попадаешь в неё сразу после «?». Прячется она тем же правилом `body:not([data-camera='overview'])`, что текст первого экрана, и носит `data-hidden-in-focus` — иначе камера оставила бы фокус на скрытом элементе.

**`localStorage` читается через `useSyncExternalStore`, а не `useState` в эффекте:** на синхронный `setState` в эффекте справедливо ругается `react-hooks/set-state-in-effect`, а серверный снимок `() => false` даёт ровно нужное — на сервере карточки нет, после гидратации она появляется сама. Флаг ставит любая из двух кнопок. Отказ хранилища (приватный режим, запрет на данные сайта) закрытие не ломает: рядом с ключом живёт модульный `dismissed`, который переживает неудачную запись.

Фон карточки — `var(--color-text-on-dark)`. Имя читается странно для подложки, но в `tokens.json` `#EDE8DF` лежит именно под `textOnDark`, а правило «токен там, где hex совпадает» важнее красоты имени.

**jsdom не реализует `showModal` и `close`.** Юнит-тест подменяет их на `HTMLDialogElement.prototype` — иначе проверить «кнопка «?» открывает справку» в нём нечем (тест домофона обходит это, проверяя тело модалки в обход `<dialog>`). Настоящее открытие, Esc и возврат фокуса на триггер проверяет Playwright.

## Как сверять с макетами

Расширение Claude in Chrome на localhost не пускает, поэтому проверка идёт через headless Chrome, запускаемый напрямую из локальной установки.

**Не сверять по dev-серверу после `npm run build`.** Сборка перезаписывает `.next`, и уже запущенный `next dev` теряет настоящие `@font-face` — в отдаваемом CSS остаются только метрические фолбэки (`local(Times New Roman)` и такой же для Golos). Текст поедет по ширине, строки начнут переноситься иначе, и диффы покажут несуществующие расхождения. Лечится перезапуском `npm run dev`; надёжнее сверять на `npm run start -- -p 3100`, где шрифты свои и картинка совпадает с продакшеном.

Статичный снимок: `--headless --disable-gpu --hide-scrollbars --virtual-time-budget=6000 --window-size=1440,900 --screenshot=<путь> <url>`. **`--virtual-time-budget` обязателен**: без него снимок делается до загрузки шрифтов, а у SVG-текста в макетах нет фолбэка, и таблички выходят засечными.

Попиксельная сверка: HTML-страница с двумя наложенными `<img>`, у верхнего `mix-blend-mode: difference`. Совпавшее становится чёрным, расхождения светятся. Так ловились смещения в 1–4 px, которые глазом не видны.

Живые состояния (ховер, скролл, клики) — через CDP: Chrome с **`--headless=new`**, `--remote-debugging-port=9222` и отдельным `--user-data-dir`, дальше скрипт на Node, который берёт `webSocketDebuggerUrl` из `http://127.0.0.1:9222/json` и говорит по встроенному в Node `WebSocket`. `Input.dispatchMouseEvent` с `type: 'mouseWheel'` даёт **настоящие** события колеса — только так проверяется снапинг и инерция; синтетические события из `Runtime.evaluate` нативный скролл не двигают. `Emulation.setDeviceMetricsOverride` фиксирует вьюпорт 1440×900, `Emulation.setEmulatedMedia` включает `prefers-reduced-motion`.

**Headless здесь обязателен, и причин две.** Окно с головой, закрытое другими окнами, перестаёт принимать `mousePressed`: `mouseMoved` доходит и попадает в нужный элемент, а нажатие молча теряется — выглядит как «кнопка не работает». И рисует такое окно субпиксельным сглаживанием, а макеты снимаются headless'ом с серым: в дифф лезут цветные каёмки у каждой буквы и у каждой рамки поля, 3.5% пикселей вместо 0.8%.

Перед снимком и замером анимации надо доводить до конца: `document.getAnimations().forEach((a) => { try { a.finish(); } catch { a.cancel(); } })`. В невидимом окне CSS-анимации стоят на нулевом кадре, и модалка измеряется в своём стартовом `translateY(8px)`. `try/catch` обязателен — у бесконечных циклов сцены `finish()` бросает, и без него до нужной анимации очередь не доходит.

Замеры вместо глазомера: `Runtime.evaluate` с `getBoundingClientRect` по обеим страницам — так сверялись прямоугольники первого экрана, и так же меряется ширина строки в реальном загруженном шрифте через `canvas.measureText`.

## Доступность

Пары контраста из `00-design-system.html` закреплены тестом `src/styles/contrast.test.ts`: он читает хексы прямо из `tokens.css`, считает WCAG и сверяет с числом из дизайн-системы до десятой. Девять пар, восемь считаются против своего фона, девятая — **граница поля против белого**, а не против бумаги: поле залито `--color-white`, и в дизайн-системе так и написано «3.7:1 к белому». Против бумаги там 3.2:1 — порог для нетекстовых элементов это всё ещё проходит.

Кольцо фокуса — **2 px `--color-lamp-text` с отступом 2 px, одинаково везде**. Пройдено Tab'ом по всем экранам: у мини-карты и у кнопок первого экрана своего правила не было и browser default рисовал 1 px тёмно-серого поверх тёмной сцены. Если добавляется новый интерактивный элемент, `:focus-visible` к нему обязателен — общего правила на всё нет намеренно, оформление у кнопок разное.

В SPEC это первоклассное требование, не пожелание. Объекты сцены фокусируемые, с `aria-label`, Enter/Space работают как клик, фокус-кольцо 2px. Контраст не ниже AA — посчитанные пары лежат в `00-design-system.html`.

`eslint-config-next` регистрирует плагин `jsx-a11y`, но включает из него только 6 правил. В `eslint.config.mjs` подключён полный набор из его `recommended` (31 правило) — повторно объявлять плагин нельзя, поэтому берутся только `rules`. Ключевые для сцены: `click-events-have-key-events`, `interactive-supports-focus`, `no-static-element-interactions`.

## Тесты

Окружение по умолчанию — `node`: контент-модель и layout-модуль сцены это чистая логика, а инициализация jsdom съедает основное время прогона. Файлу с рендером компонентов нужен докблок `// @vitest-environment jsdom` в первой строке — см. `src/test/smoke.test.tsx`.

Конфиг лежит в `vitest.config.mts`, а не `.ts`: иначе Vite грузит его как CommonJS и предупреждает про ESM-синтаксис.

**Playwright живёт в `e2e/` и в pre-push не входит.** Он поднимает свой сервер (`npm run build && npm run start -- -p 3101`) с пустыми `TELEGRAM_*`, и держать это в каждом пуше дороже, чем пользы; гоняется руками через `npm run e2e`. Браузер — `channel: 'chrome'`, локальная установка: тем же Chrome идёт сверка с макетами, и 130 МБ движка Playwright качать незачем.

Тексты в сценариях берутся из `src/content/ru`, а не переписываются строками: иначе правка словаря ломает тест молча. Селекторы ролей надо сужать до `getByRole('dialog')` — «Позвонить» есть и в шапке, и в форме, и strict mode справедливо ругается.
